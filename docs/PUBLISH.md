# 公开源码审计

2026-11-24 按路径、类型和大小盘点了工作区，包括未跟踪和被忽略的文件。另检查了原 `master` 截至 `43d21c3` 的全部 17 个提交、文件路径和 90 个不同的文件对象。本机签名材料和大型构建产物均在 Git 历史之外。

| 排除项 | 原因 |
| --- | --- |
| `.signing/`、密钥库和密码文件 | `release.p12` 及其口令仅供本机签名。公开的 `tools/signing.sh` 会为构建者生成自己的签名。 |
| 账号 vault、凭据文件、私有环境配置 | 这些文件可能包含邮箱、密码或会话令牌，属于各自的账号。 |
| `dist-apk/`、`apk-parts/` | 完整 APK 作为 Release 附件分发，分片只用于传输。 |
| `runtime-cache/`、`.cache/`、`.gradle/`、各级 `build/` | DSH 二进制、rootfs、软件包、模拟器镜像和编译产物可由锁文件或相应工具重新取得。 |
| `docs/CODEX_BRIEF*.md` | 内部协作笔记保存在本机 `master`。 |

`v0.1.0-test` 的公开历史从独立根提交 `9128ca0` 开始。已复核其完整文件清单和内容，未发现真实 API 密钥（含 OpenAI）、访问令牌、账号邮箱或密码、签名私钥、口令或 vault 数据。测试中的鉴权样例和保留域名邮箱均为测试数据。提交的二进制文件只有 Gradle Wrapper JAR 和一张 2×2 像素的测试 JPEG。

`v0.1.1-test` 的公开提交接在该根提交之后。审计覆盖这两次公开提交可达的文件对象。诊断与测试源码随版本发布，授权交接文件、逐帧记录、图片附件、内部协作笔记与构建目录均已排除。APK 通过 GitHub Release 附件分发。

`v0.1.2-test` 接在 `aa99b54` 之后。发布审计检查了公开提交可达的路径、文件大小、二进制文件和凭据特征。新增运行时内容以构建脚本、C 源码和绑定校验代码提交。签名 APK 单独作为 prerelease 附件上传。

# 在手机上发送附件

每条消息可添加 **9 张相册或相机照片、4 个文档**。相册支持多选，拍照会追加到当前草稿。发送前可逐项移除。点击文件名可查看正文，再点正文里的 `[图 1]` 即可看图。已发送消息的缩略图支持全屏、双指缩放和左右滑动。

| 文件 | 正文和图片的位置 |
| --- | --- |
| TXT、Markdown、CSV、TSV、JSON、YAML、日志及常见代码 | 读取 UTF-8 或带 BOM 的 UTF-16，保留换行、制表符和缩进。 |
| DOCX | 按正文段落和文字的顺序，在绘图或旧式图片引用处读取 `word/media/` 中对应的图片。 |
| PPTX | 按演示文稿的幻灯片顺序和页内形状顺序，在引用处插入 `ppt/media/` 中对应的图片。 |
| XLSX | 按工作簿和单元格顺序读取已保存的值。浮动图片按绘图起始行、列插入对应单元格文字之前，空行、空单元格也可定位。仅有绝对坐标的图片按默认行高和列宽换算位置。 |
| PDF | 读取前 64 页，按图片在页面上的位置与文字合排，支持图像对象、嵌套表单和 PDF 行内图。若这些页均无可提取文字，改为渲染前 **最多 3 页**，每页发送一次。单页正文超过 16,384 个字形时截断。 |
| 旧版 DOC | 可读取以 .doc 为后缀保存的纯文本。Word 97–2003 二进制文档需先另存为 DOCX。 |

每个文档最多保留 **10 张内嵌图**，从 `[图 1]` 开始按出现位置连续编号。短边不足 **64 像素**的内嵌图、无法解码的图片、Office 外链和未引用的媒体均跳过。相同图片在两处出现时各占一个位置。文档原先写下的 `[图 1]` 仍是普通文字。照片、内嵌图和扫描页均保存为长边最多 **1,600 像素**、每张最多 **768 KiB** 的 JPEG。

单个原文件限 16 MiB。Office 包限 2,048 个条目，读取的 XML 合计限 24 MiB，候选图片的解包数据合计限 64 MiB。每个文档在本机保留最多 131,072 个 UTF-16 单元的正文前缀，截断处标记「…」。

## 发送给 DSH 的内容

问题、各附件的文字和 JPEG 在同一个 `session/prompt` 中按顺序发送。每份正文以 `[文件：文件名]` 开头，遇到占位就发送对应图片，然后继续发送后文。扫描 PDF 发送文件名和整页图。图片识读使用当前模型的图片输入能力。

- 整轮最多 **20 张图**。先给全部手选照片留位，再按附件顺序为内嵌图和扫描页分配余位。因此先加文件、后加照片，也能保留手选照片。
- 沿用现有上下文预算。先预留问题、文件名、手选照片和各文件的最短正文，再按可用空间决定文档图片数。正文合计最多发送 **64 KiB UTF-8**，另受当前模型触发值四分之一和剩余空间限制。短文件优先取全，长文件平分余量。
- 只发送正文前缀内有完整占位的图片。图片超额或刚好在占位中途截断时，该图和它的占位一同略过。本机正文和已提取的 JPEG 仍可查看。
- 回合结束后，DSH 卸载旧图，原位置的 `[图 1]` 等文字仍在。之后进行区段压缩时，旧正文和图号一同作为摘要输入。手机历史保留完整的本机附件。删除对话或移除草稿会清理独占文件，共享文件保留到最后一个引用被移除。[上下文策略](CONTEXT.md)

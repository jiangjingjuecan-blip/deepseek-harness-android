# 发送与逐字显示

点「发送」先显示用户气泡和「正在回复…」，清空输入框与附件栏，并触发轻触反馈。该帧绘制后，后台事务才写入消息、清空草稿并转移附件。尚在导入的照片或文档在用户气泡上显示数量和进度，失败可点气泡上的「重试」。已入库的用户行和附件会沿用。共享历史里的失败回复再次生成时会保留旧分支。首次写库就失败的气泡由当前应用进程保留，重试成功后落盘。

生成时，发送键变为「停止」。点按会取消本轮请求，保留已收到的正文和中断状态。手机回车换行，输入法组合输入期间只用发送键提交。输入框和附件栏随草稿平滑收合。

距底部 48 dp 以内跟随新内容。向上翻过这段距离后，阅读位置固定，右下角出现向下箭头。点箭头恢复跟随。

新回复和重生成默认每秒显示约 8 个汉字，英文词内的字母较快。积压时平滑加速，每批已收到的文字在约 4 秒内追上。流结束后的余字在约 420 毫秒内收尾，实际显示受屏幕帧率影响。轻点回复立即补全，此后新到的文字也直接显示。长按仍打开消息菜单。历史和已完成的分支版本直接显示全文。

设置中的「显示速度」可选每秒 4、8、16 字或「即时」。选择存入 `ui` SharedPreferences 的 `reveal_speed`，0 表示即时。网络接收、SQLite 检查点与画面刷新各自独立。界面在每个 Choreographer 帧最多向活动回复追加一次正文。

## 0.1.6 基线

发送键只有向上的箭头。生成期间 `updateSend()` 禁用它。点发送后，主线程先查 SQLite 附件草稿，写入用户行、待回复行和草稿清空，再刷新输入框和线程。流式通知会重新查询全部消息，逐行比较显示文字。只有内容发生变化的 TextView 才调用 `setText`。靠近底部时，布局后用 `scrollTo` 直接移到末尾。

设备采样由独立仪器 APK 完成。起点是触摸抬起，终点是主窗口开始绘制且用户正文与线程视口相交。Choreographer 分别采样发送后 500 毫秒和首次画出回复前缀后的 2 秒。帧间隔按 60 Hz 四舍五入，跨过至少两个刷新周期记一次长间隔。此指标不能测量屏幕实际亮起的时刻。

| 0.1.6 单次采样 | 抬起到气泡绘制 | 发送长间隔 / 总间隔 | 流式长间隔 / 总间隔 |
| --- | ---: | ---: | ---: |
| 首轮，键盘尚在启动 | 2547.1 ms | 1/2 | 4/4 |
| 第 2 轮 | 1172.3 ms | 1/1 | 5/5 |
| 第 3 轮 | 839.4 ms | 1/2 | 5/5 |

第 2、3 轮输入法占用的底部区域都是 622 px。发送采样期间焦点留在输入框，窗口底边和输入框纵坐标的最大位移均为 0 px。软件模拟器一帧有时已超过整个 500 毫秒观测窗，跨窗的帧按完整间隔计入。

## 0.1.7 实测

在同一 Android 10 ARM64 模拟器 `harnessarm` 上以相同的仪器采样（5 轮连发，含气泡滚动步数）测得：

| 0.1.7 采样 | 抬起到气泡绘制 | 发送长间隔 / 总间隔 | 流式长间隔 / 总间隔 | 滚动步数 / 最大步长 |
| --- | ---: | ---: | ---: | ---: |
| 第 1 轮 | 638.5 ms | 1/2 | 18/21 | 0 / 0 px |
| 第 2 轮 | 325.1 ms | 4/5 | 20/23 | 2 / 99 px |
| 第 3 轮 | 446.5 ms | 2/2 | 22/26 | 1 / 74 px |
| 第 4 轮 | 422.6 ms | 3/4 | 24/24 | 1 / 74 px |
| 第 5 轮 | 297.5 ms | 5/6 | 19/23 | 4 / 90 px |

5 轮中位抬起到气泡绘制为 **422.6 ms**（对比 0.1.6 同口径 5 轮中位数 1032.1 ms），输入法占用底部区域 402 px，所有轮次 `insetDelta=0`、`inputDelta=0`、`focus=true`。在独立 `send-ui` 仪器测试中，默认 8 字/秒档位对 24 字中文回复实测展开速率为 **8.23 字/秒**（2065 ms 内由 3 字展开至 20 字）。
